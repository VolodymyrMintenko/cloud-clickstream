Every query is broken for users who are not global admins.

All seven query functions declare the caller parameters bound to token claims, and callerIsAdmin is declared NOT NULL. Auth0 only puts the global_admin claim on admin tokens, so an ordinary user's token simply has no such claim, and the server refuses the whole call. This is the proof from a deployment log:

  com.datasqrl.server.auth.AuthMetadataReader | Required claim 'https://datasqrl.com/global_admin' is not present on authorization
  POST /v1/mcp HTTP/1.1 403

So today every non admin gets a 403 on every query, which is most of the users.

Make the claim parameters tolerate an absent claim. callerIsAdmin must be nullable and a missing claim must read as not an admin, so the filter behaves as it does for a user whose claim is false. Do the same for the data_group_ids claim, since a user who belongs to no organization may have no such claim either, and a missing list must behave like an empty list rather than failing the call. Leave sub as it is, since every token carries it.

Keep the access rule itself exactly as it is: an admin sees every row, everyone else sees rows whose org_id is in their groups or whose user_id is their own sub.

Add API tests for a token without the global_admin claim and for a token without the data_group_ids claim, proving the call succeeds and returns only what that caller may see. Re-run the tests refreshing only the snapshots this legitimately changes.
