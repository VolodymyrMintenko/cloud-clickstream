Apply the caller scoping to the four query functions that still miss it.

TopProjectsByUser, UserTrail and OrgTrail already read the caller's claims and filter rows by them. SessionJourney, TopPages, PageTransitions and ActiveUsers do not, so SessionJourney hands anyone who knows a session id another person's full trail, and the three aggregates count across every organization at once, which lets a member of one company read platform wide usage.

Give all four the same treatment the scoped three already use: the same hidden caller parameters bound to sub, https://datasqrl.com/data_group_ids and https://datasqrl.com/global_admin, and the same rule. A caller whose global_admin claim is true sees every row. Everyone else contributes only rows whose org_id is in their data_group_ids, or whose user_id equals their sub, so a person still sees their own page views on pages that have no organization.

For the three aggregates this means the counts are computed over the rows the caller is allowed to see, so each caller gets the numbers for their own organizations and an admin gets the whole picture. Keep every existing argument, returned column and ordering as it is.

Add API tests showing an aggregate counted for a member of one organization differs from the same aggregate counted for an admin, and that SessionJourney returns nothing for a session belonging to an organization the caller is not in. Update the README, and re-run the tests refreshing only the snapshots this legitimately changes.
