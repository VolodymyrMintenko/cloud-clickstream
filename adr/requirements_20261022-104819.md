Let a caller ask about themselves without knowing their own id.

UserTrail and TopProjectsByUser require userId as an argument. The assistant that calls these over MCP has no way to learn the caller's id, so it literally sends the string CURRENT_USER_ID_PLACEHOLDER, gets nothing back and then asks the person to type their own id, which nobody knows.

The queries already read the caller's sub claim for access scoping, so the id is right there. Make userId optional on both: when it is omitted, the query returns the caller's own rows, using the sub claim. When it is given, it keeps working exactly as it does now, still subject to the same access rule, so a caller can still ask about a colleague in an organization they share.

Say this plainly in both docstrings, since those descriptions are what the assistant reads to decide how to call the tool: state that userId is optional and that leaving it out means the caller themselves. Add an API test calling UserTrail with no userId, update the README, and re-run the tests refreshing only the snapshots this legitimately changes.
